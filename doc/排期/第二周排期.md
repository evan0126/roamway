## 3. 关键学习方式

### 前端：只补 React 与 Next.js 差异

不再单独讲授 JS/TS 语法、类型定义、数组方法、组件传参、基础输入绑定、草稿和确认取消。React 的状态快照、函数式更新、引用比较、key 与状态重置、Hook 使用规则及副作用清理在实际需要时解释。

详情页保留服务端读取路由与取数职责，编辑组件承担客户端交互。重点理解客户端依赖边界、服务端到客户端的 props 限制，以及首次预渲染与 hydration。前端请求接入后，再学习数据获取位置、缓存/刷新和路由加载与错误边界。

标题、目的地、天数、预算和每日安排仍是项目必要字段；编辑、校验、取消及两条行程的状态隔离在第三周集中补齐并验证，不作为先学后端的前置条件。具体天数范围与零预算规则在接口模型实现前明确，前后端保持一致。

### 后端：先独立验证，再连接浏览器

保留 `backend/basics.py` 作为基础语法记录，复用 `backend/trip.py` 中适合的业务函数；接口入口文件在实现时确定，不覆盖已有练习。教学用模块加载输出不直接带入接口流程。

FastAPI 等依赖仅安装到本项目虚拟环境并记录依赖清单，实现前说明用途与目录变化；本次计划调整不安装依赖。模型负责输入输出校验，业务函数处理业务规则，接口层负责请求与响应。

| 用途 | 方法与路径 | 需要观察的行为 |
| --- | --- | --- |
| 健康检查 | GET /health | 服务正常响应 |
| 新建行程 | POST /trips | 返回新行程及其标识 |
| 行程列表 | GET /trips | 返回已有行程，允许空列表 |
| 行程详情 | GET /trips/{id} | 返回指定行程；不存在时返回 404 |
| 完整更新 | PUT /trips/{id} | 完整合法数据更新原行程，保留标识；不存在时返回 404 |

每日安排与旅行天数使用不同字段，检查每日安排数量与旅行天数一致。本阶段不增加数据库、登录、模型调用或额外接口。
