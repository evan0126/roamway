# doc 目录约束

本文件适用于 `doc/` 及其所有子目录。新增或修改文档、截图时，先检查同类文件的现有命名，沿用统一格式。

## 1. 文件与目录命名

- 业务文档使用简洁的中文名称和 `.md` 扩展名，例如 `需求文档.md`、`学习计划.md`。
- 保留现有分类目录：`排期/`、`学习记录/`。同类内容放到已有目录，不重复创建近义目录。
- 总排期固定为 `排期/学习排期表.md`。
- 每周排期使用阿拉伯数字，格式为 `排期/第N周排期.md`，例如 `第1周排期.md`、`第2周排期.md`、`第14周排期.md`；其中 N 替换为阿拉伯数字。
- 每日学习记录目录按排期日期归档，使用补零的 `MM.DD` 格式，例如 `学习记录/10.15/`、`学习记录/01.05/`。提前或延期学习不改变目录名。
- 学习笔记统一按 `笔记（主题）.md` 命名，主题根据实际学习内容使用简短中文，例如 `笔记（环境准备）.md`、`笔记（路由与布局）.md`、`笔记（接口与请求模型）.md`。每个排期日期目录只保留一份笔记，当天不同主题按章节合并并持续更新；主题扩展时可调整文件名并同步引用。正文标题使用对应主题，分节说明各部分进度，未全部完成时不标记整篇完成。
- 禁止使用随机字符串、哈希、系统截图时间戳，以及“新建文档”“最终版”“副本”等无明确含义的名称。
- `AGENTS.md` 等工具约定文件保留其标准名称。

## 学习日期记录

- 每篇学习笔记开头必须分别记录 `排期日期`、`实际学习日期`、`实际完成日期`，日期统一为 `YYYY-MM-DD`。
- 实际日期以用户所在时区为准，本项目默认使用 `Asia/Shanghai`；不能直接把排期日期当作实际日期。
- 跨天学习时，实际学习日期记录日期范围或多个具体日期。
- 尚未完成时填写 `实际完成日期：未完成`；用户确认完成后，记录实际完成当天的日期。
- 补录历史笔记优先依据既有记录和用户确认；日期无法确定时填写 `待确认`，不推测。

## 笔记内容详略

- 每日笔记以“当日学习计划及完成情况”和“学习笔记”为主，结构简单，篇幅适中。
- 用简洁表格记录当天任务、状态和实际完成情况；完整长期计划留在学习计划与排期文档，不复制到每日笔记。
- 重要过程保留关键操作、必要原理、核心代码、遇到的问题与处理方式、实际结果和对应截图，便于复习；不展开成完整教程，也不只留完成清单。
- 合并重复讲解和过时状态，不流水记录对话；明确区分实际完成、预期结果和待验证事项。
- 可对当天首次学习或刚理解的新知识点作简短总结，突出作用、关键区别与使用场景；不重复总结已掌握的 JS/TS 等基础，不扩展未学内容。
- 接口学习中补充的 Python 通用基础语法归入已有基础笔记，注明实际补充日期；当天接口笔记保留应用代码和链接，避免重复展开语法讲解。

## 2. 截图命名

- 截图与对应日期的学习笔记放在同一目录。
- 截图按归档顺序命名为 `截图1.png`、`截图2.png`，以此类推；序号从 1 开始，不补零。
- 扩展名使用小写，并与真实图片格式一致；JPEG、WebP 等图片分别使用 `.jpg`、`.webp`，不能仅修改扩展名冒充格式转换。
- 同一天的截图序号跨格式连续递增，不重复使用编号，不覆盖已有图片。
- 用户提供的随机附件名在归档时应改为上述格式。
- 笔记使用相对路径引用截图，例如 `![旅行需求预览组件代码](./截图1.png)`，并提供能说明内容的替代文字。

## 3. 修改与检查

- 文档使用 UTF-8 编码，保持中文可读。
- 重命名或移动文件时，同步更新所有指向该文件的文档链接和图片引用。
- 只调整当前任务涉及的文件，避免无关的批量重命名。
- 完成后检查文件名、图片真实格式、链接目标是否存在，以及是否有旧路径残留。

```text
│   └── 第2周排期.md

    │   ├── 截图1.png
    │   └── 截图2.png
    └── 10.15/
        ├── 笔记（组件与表单）.md
        └── 截图1.png
```
