## 3. 关键学习方式

### 前端：先展示，再编辑

先在现有 `src/app/trips/[id]/page.tsx` 完成固定数据渲染，再抽出卡片与编辑组件。详情页继续负责读取路由编号和选择行程；需要状态和事件的部分由客户端组件承担，避免将整个异步详情页直接改成客户端组件。

旅行需求表单沿用首页已学内容。编辑组件持有独立草稿，修改嵌套数组时创建新的数组及目标对象；确认更新页面状态，取消恢复草稿。本周的确认只更新客户端状态，不宣称已经写入后端或持久化。

标题、目的地必填；天数需为限定范围内的整数；预算需为有限且合法的数值。具体天数上下限及是否允许零预算在实现前结合现有表单确定，并在前后端保持一致。已有校验可复用，不重复编写同类逻辑。

### 后端：先独立验证，再连接浏览器

保留 `backend/basics.py` 作为基础语法记录，复用 `backend/trip.py` 中适合的业务函数；接口入口与教学用启动脚本的具体文件安排在实现时确定，避免覆盖已有练习。展示模块加载的教学输出不直接带入正式接口流程。

FastAPI 等依赖仅安装到该项目的 Python 虚拟环境，并记录依赖清单；本次排期编写不执行安装。实现前先说明依赖用途与目录变化。模型负责参数校验，业务函数处理业务规则，接口层负责请求与响应。

本周计划的最小接口集合如下；具体字段结构随模型练习确定，在第三周接入前固定。

| 用途 | 方法与路径 | 需要观察的行为 |
| --- | --- | --- |
| 健康检查 | GET /health | 服务正常响应 |
| 新建行程 | POST /trips | 返回新行程及其标识 |
| 行程列表 | GET /trips | 返回已有行程，允许空列表 |
| 行程详情 | GET /trips/{id} | 返回指定行程；不存在时返回 404 |
| 完整更新 | PUT /trips/{id} | 使用完整合法数据更新原行程，保留标识；不存在时返回 404 |

每日安排使用独立字段表达，避免与旅行天数混用同一个名称。编辑与接口数据需覆盖标题、目的地、旅行天数、预算、每日安排；检查每日安排数量与旅行天数一致。暂不增加数据库、登录、模型调用或额外接口。
