# Next.js 与 Python 学习计划

学习主线为 Next.js 前端与 Python 后端。基于已有 JS、TS 和 Vue 基础，通用前端知识不再安排独立课程；React 只补与 Vue 不同且当前功能需要的机制。

**调整依据（2026-10-19）：** 用户要求跳过已掌握的前端基础，后续重点为 Next.js、Python 接口、数据库、模型、RAG 与 Agent。本次只调整计划和排期，不新增或更新每日学习笔记，不据此将未验收的功能标为已完成。

## 学习取舍

| 内容 | 后续安排 |
| --- | --- |
| JS/TS 语法、类型定义、数组方法、对象展开、模块导入导出 | 从必修课程排除，遇到具体问题再查阅 |
| 列表与条件渲染、组件传参、纯展示组件拆分 | 不再单独讲解或布置重复练习 |
| 受控输入、标题/预算编辑、编辑草稿、确认取消、必填与数值校验 | 不再逐个字段教学；项目所需功能在接口联调时集中实现和验证 |
| React 与 Vue 的差异 | 按需补状态快照、函数式更新、引用比较、key 与状态重置、Hook 使用规则及副作用清理；不再重复基础表单示例 |
| Next.js 特有机制 | 保留 App Router、布局与动态路由、Server/Client Component 边界、可序列化 props、预渲染与 hydration；联调时补数据获取、缓存/刷新及路由加载与错误边界 |
| HTTP、JSON、浏览器请求、加载和错误提示等通用前端知识 | 不设基础课，在 FastAPI 请求响应、状态码及 Next.js 联调中直接应用 |
| Python、FastAPI/Pydantic、SQL/数据库、模型、RAG、Agent | 保留现有学习主线；Python 已完成部分不重学，不根据前端基础推断后端已掌握 |

跳过教学不等于删除产品功能，也不等于验收通过。各阶段只检查新增知识和实际功能结果；不再要求通过通用前端基础测验才能继续。

**执行安排：** 按[学习排期表](./排期/学习排期表.md)分 9 个阶段推进（沿用原周次编号），目标于 2026-12-10 完成，每周可投入 10～15 小时，作为时间上限参考，不为填满时长重复基础练习。下面 8 个学习步骤按主线推进，步骤编号不等于排期阶段编号；跳过的课程不占日期，未完成课程连续前移，已有笔记的历史日期保留。最后阶段用于测试与缓冲。

- [x] 确定独立项目目录：当前前端位于 `roamway/`，后端位于项目内的 `backend/`，沿用现有位置。
- [ ] 检查 Node、pnpm、Python 和 Git，按所选 Next.js 版本核对 Node 要求。
- [x] 创建 Next.js + TypeScript 项目，并创建 Python 虚拟环境。
- [x] 在 Next.js 页面中编写旅行需求表单，修改天数后页面立即显示新值。
- [x] 完成 Python 零基础入门课（1.5 小时）：变量、字符串、数字、布尔值、None、print、缩进与 if，初识列表、字典和 for；在 `backend/basics.py` 中输出旅行条件，并根据天数判断是否合法（代码与运行记录已核对，用户于 2026-10-16 确认课程完成）。
- [x] 用 Python 写一个函数，接收目的地和天数，返回字典；非法天数抛出可理解的异常。

**完成检查：** 两端可以分别运行；能解释 Next.js 客户端组件中的状态更新，以及 Python 字典、类型标注和异常的作用。

辅助资料：[Next.js 官方 React 基础教程（按需查阅）](https://nextjs.org/learn/react-foundations)。

- [x] 创建旅游助手、攻略资料、我的行程三个页面。
- [x] 完成行程列表到详情的页面跳转。
- [ ] 在现有页面中确认服务端负责取数、客户端负责交互的边界，能解释组件导入链和 props 传递限制。
- [ ] 在接口联调时理解数据获取位置、缓存与刷新、加载和错误边界，区分组件状态更新与服务端数据更新。

**移出独立课程：** 旅行需求表单/每日卡片/来源组件拆分，固定数据 map 渲染，标题/安排/预算逐字段编辑，必填/天数/预算校验。这些仍按产品需要实现，但不作为进入后端课程的前置关卡；来源组件在 RAG 阶段随真实引用实现，不补做固定来源展示练习。

**完成检查：** 已有路由可用，能结合代码说明 Server/Client 边界和 hydration；数据获取与刷新项在第 3 步联调时检查，不阻塞先开发 Python 接口。

## 第 3 步：开发 Python 接口，完成前后端联调

**学习：** FastAPI 路由、Pydantic 运行时校验、请求体与路径参数声明、异常响应、Python async/await。HTTP 方法、状态码、JSON 和浏览器请求不另设基础课，直接结合接口实践；CORS 与 Next.js 数据获取边界在联调时学习。

- [ ] 创建 FastAPI 服务和健康检查接口。
- [ ] 定义行程输入与输出结构，包括标题、旅行条件、每日安排和预算。
- [ ] 实现新建、列表、详情、更新接口；本阶段用内存保存，下一步替换为数据库。
- [ ] 使用接口文档分别测试正常输入、非法输入和不存在的行程。
- [ ] 前端接入接口，替换固定示例数据，明确服务端取数与客户端提交的位置，并处理更新后的页面数据刷新。
- [ ] 集中补齐项目所需的旅行需求输入、标题/每日安排/预算编辑及校验，不再逐字段教学；后端保持相同输入规则。
- [ ] 加入加载、空列表、请求失败状态，提交期间禁止重复操作；结合 Next.js 路由加载与错误边界实现，不重复通用前端交互课程。

**完成检查：** 页面可以新建和修改行程；非法参数被后端拒绝；关闭后端时前端显示失败提示。

资料：[FastAPI 教程](https://fastapi.tiangolo.com/tutorial/)，重点阅读请求体、响应模型、错误处理和 CORS。

## 第 4 步：接入 PostgreSQL，完成持久化

**学习：** 主键、关联、SQL、事务、数据库连接、数据库迁移、数据访问与业务逻辑分离。

- [ ] 创建独立 PostgreSQL 数据库，连接配置放入后端环境变量。
- [ ] 手写一次插入、查询和更新，理解数据如何进入数据库。
- [ ] 选择一种数据库访问方式，为行程建立持久化结构。
- [ ] 创建初始数据库迁移，替换内存存储。
- [ ] 将行程读写收敛到数据访问模块，接口调用业务模块。

**完成检查：** 保存后重启后端、刷新页面，行程仍存在；能用 SQL 查到对应数据；保存失败不会留下部分写入。

## 第 5 步：接入模型，生成结构化行程

**学习：** 模型 API、提示词、上下文、Token、结构化输出、参数校验、超时处理。

- [ ] 选择一个模型供应商，先用独立 Python 脚本完成一次调用。
- [ ] 将密钥放在后端环境变量中，提供不含密钥的配置示例。
- [ ] 定义行程输出结构，使用 Pydantic 校验模型结果。
- [ ] 实现生成接口，将旅行条件传给模型；此阶段先展示为普通 AI 建议。
- [ ] 检查生成天数和输入一致，每天包含上午、下午、晚上。
- [ ] 用代码计算总预算估算，标记估算费用和待核实信息。
- [ ] 前端展示生成结果，复用已有编辑和保存能力。
- [ ] 处理超时、调用失败和格式错误，不自动保存失败结果。

**完成检查：** 输入三天得到三天；错误输出不会被当作成功；浏览器中看不到模型密钥。

## 第 6 步：导入攻略，理解知识库入库

**学习：** 文件上传、UTF-8、文本切分、Embedding、向量维度、资料与片段关联。

- [ ] 准备 5～10 篇同一城市的 Markdown 或 TXT 攻略。
- [ ] 实现上传和资料列表，保存标题、来源、正文与处理状态。
- [ ] 先将一篇攻略切分成片段，打印并检查片段是否保留必要上下文。
- [ ] 调用 Embedding 模型，将文本片段转换为向量。
- [ ] 选择一种向量存储方案，保存向量、原文和资料标识。
- [ ] 完整处理成功后将资料标为可用；失败时记录原因并提供重试。
- [ ] 验证重试不会重复增加该资料的检索片段。

**完成检查：** 能查看一篇攻略对应的原文片段和向量；处理失败的资料不进入后续检索。

## 第 7 步：实现 RAG 问答，接入行程生成

**学习：** 问题向量化、相似度检索、Top-K、上下文组织、引用、检索效果评估。

- [ ] 把用户问题转换为向量，检索相关攻略片段。
- [ ] 先直接查看检索结果，确认片段与问题相关，再接模型。
- [ ] 将问题和片段一起传给模型，要求依据资料回答。
- [ ] 后端校验来源标识，前端展示真实标题和原文片段。
- [ ] 对无关问题、空知识库和资料不足给出明确提示。
- [ ] 将检索能力接入行程生成，替换前一步的普通 AI 建议。
- [ ] 手动编辑某项安排后移除该项原引用，避免来源错配。
- [ ] 准备三类问题：资料明确覆盖、只覆盖部分、完全未覆盖，记录检索和回答结果。

**完成检查：** 雨天问题能引用攻略中的雨天建议；无相关资料不编造来源；能分辨是检索错误还是生成错误。

## 第 8 步：实现单 Agent，完成演示和测试

**学习：** 工具定义、参数结构、工具调用结果、执行循环、状态、停止条件、确认机制。

- [ ] 将检索攻略、读取行程、保存行程封装为三个工具，复用已有业务函数。
- [ ] 定义每个工具的用途和参数，由 Python 校验和执行。
- [ ] 实现“调用模型 → 执行工具 → 返回结果 → 继续或结束”的循环。
- [ ] 设置每任务工具调用上限和超时，遇到未知工具或非法参数明确报错。
- [ ] 保存工具先返回待确认内容；用户确认后，程序才允许保存，模型不能自行确认。
- [ ] 保存内容或目标改变后重新确认，避免重复保存。
- [ ] 页面展示实际执行状态，后端记录工具、耗时和结果状态。
- [ ] 用测试替身模拟工具失败、模型失败和达到调用上限，避免测试依赖付费调用。
- [ ] 完整演示一次检索、生成、编辑、确认保存和重新查看。
- [ ] 编写运行说明：环境要求、安装步骤、数据库迁移、配置与启动命令。

**完成检查：** Agent 能实际调用工具；取消确认不写入；达到上限会停止；失败可以定位到具体步骤。

资料：[Agent 与工作流设计](https://www.anthropic.com/engineering/building-effective-agents)。
