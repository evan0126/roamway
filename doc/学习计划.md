- [ ] 创建初始数据库迁移，替换内存存储。

## 第 5 步：接入模型，生成结构化行程

**学习：** 模型 API、提示词、上下文、Token、结构化输出、参数校验、超时处理。

- [ ] 选择一个模型供应商，先用独立 Python 脚本完成一次调用。
- [ ] 将密钥放在后端环境变量中，提供不含密钥的配置示例。
- [ ] 定义行程输出结构，使用 Pydantic 校验模型结果。
- [ ] 实现生成接口，将旅行条件传给模型；此阶段先展示为普通 AI 建议。
- [ ] 检查生成天数和输入一致，每天包含上午、下午、晚上。
- [ ] 用代码计算总预算估算，标记估算费用和待核实信息。
- [ ] 前端展示生成结果，复用已有编辑和保存能力。
- [ ] 处理超时、调用失败和格式错误，不自动保存失败结果。

**完成检查：** 输入三天得到三天；错误输出不会被当作成功；浏览器中看不到模型密钥。

## 第 6 步：导入攻略，理解知识库入库

**学习：** 文件上传、UTF-8、文本切分、Embedding、向量维度、资料与片段关联。

- [ ] 准备 5～10 篇同一城市的 Markdown 或 TXT 攻略。
- [ ] 实现上传和资料列表，保存标题、来源、正文与处理状态。
- [ ] 先将一篇攻略切分成片段，打印并检查片段是否保留必要上下文。
- [ ] 调用 Embedding 模型，将文本片段转换为向量。
- [ ] 选择一种向量存储方案，保存向量、原文和资料标识。
- [ ] 完整处理成功后将资料标为可用；失败时记录原因并提供重试。
- [ ] 验证重试不会重复增加该资料的检索片段。

**完成检查：** 能查看一篇攻略对应的原文片段和向量；处理失败的资料不进入后续检索。

## 第 7 步：实现 RAG 问答，接入行程生成

**学习：** 问题向量化、相似度检索、Top-K、上下文组织、引用、检索效果评估。

- [ ] 把用户问题转换为向量，检索相关攻略片段。
- [ ] 先直接查看检索结果，确认片段与问题相关，再接模型。
- [ ] 将问题和片段一起传给模型，要求依据资料回答。
- [ ] 后端校验来源标识，前端展示真实标题和原文片段。
- [ ] 对无关问题、空知识库和资料不足给出明确提示。
- [ ] 将检索能力接入行程生成，替换前一步的普通 AI 建议。
- [ ] 手动编辑某项安排后移除该项原引用，避免来源错配。
- [ ] 准备三类问题：资料明确覆盖、只覆盖部分、完全未覆盖，记录检索和回答结果。

**完成检查：** 雨天问题能引用攻略中的雨天建议；无相关资料不编造来源；能分辨是检索错误还是生成错误。

## 第 8 步：实现单 Agent，完成演示和测试

**学习：** 工具定义、参数结构、工具调用结果、执行循环、状态、停止条件、确认机制。

- [ ] 将检索攻略、读取行程、保存行程封装为三个工具，复用已有业务函数。
- [ ] 定义每个工具的用途和参数，由 Python 校验和执行。
- [ ] 实现“调用模型 → 执行工具 → 返回结果 → 继续或结束”的循环。
- [ ] 设置每任务工具调用上限和超时，遇到未知工具或非法参数明确报错。
- [ ] 保存工具先返回待确认内容；用户确认后，程序才允许保存，模型不能自行确认。
- [ ] 保存内容或目标改变后重新确认，避免重复保存。
- [ ] 页面展示实际执行状态，后端记录工具、耗时和结果状态。
- [ ] 用测试替身模拟工具失败、模型失败和达到调用上限，避免测试依赖付费调用。
- [ ] 完整演示一次检索、生成、编辑、确认保存和重新查看。
- [ ] 编写运行说明：环境要求、安装步骤、数据库迁移、配置与启动命令。

**完成检查：** Agent 能实际调用工具；取消确认不写入；达到上限会停止；失败可以定位到具体步骤。

资料：[Agent 与工作流设计](https://www.anthropic.com/engineering/building-effective-agents)。
