# 需求文档

## 1. 项目目标

用户输入旅行需求，助手参考旅游攻略生成行程，用户可以修改、保存并重新查看。

## 2. 第一版范围

- 单人本地使用，暂不做登录。
- 只支持一个城市，例如成都。
- 支持 1～5 天的旅行计划。
- 使用自己整理的 5～10 篇攻略。
- 使用独立数据库。
- 不做预订、支付、实时价格、地图和天气。

## 3. 核心功能

| 功能 | 简单需求 | 学习知识点 |
|---|---|---|
| 攻略导入 | 上传 Markdown 或 TXT，查看处理状态 | 文件上传、Python 校验、文本切分、Embedding |
| 攻略问答 | 根据资料回答问题，展示来源片段 | RAG、检索、提示词、空结果处理 |
| 行程生成 | 输入天数、人数、总预算、兴趣，生成每日安排 | 表单、模型调用、结构化输出 |
| 行程管理 | 手动编辑、保存、查看已保存行程 | API、数据库、CRUD |
| Agent 执行 | 根据需要检索攻略、读取已有行程，经确认后保存 | 工具调用、状态管理、停止条件、用户确认 |

预算标为估算；资料不足时明确说明，不编造来源或实时信息。

## 4. 页面

1. **旅游助手**：输入需求、提问、展示行程和引用。
2. **攻略资料**：上传资料、查看处理状态。
3. **我的行程**：查看和编辑已保存行程。

## 5. Agent 的最小能力

| 工具 | 作用 |
|---|---|
| 检索攻略 | 获取与用户需求相关的资料 |
| 读取行程 | 获取指定的已保存行程 |
| 保存行程 | 用户确认后保存当前方案 |

模型选择工具，Python 校验并执行。页面展示“正在检索攻略”“正在生成行程”等状态；失败时提示原因。每次任务设置工具调用上限，达到上限后停止并告知用户。

## 6. 技术分工

- **Next.js + TypeScript**：页面与交互。
- **Python + FastAPI**：业务接口、知识库、Agent 执行。
- **PostgreSQL**：攻略信息、文本片段和行程。
- **模型 API + Embedding**：生成内容与语义检索。

具体模型、向量存储和框架在实现阶段选择。

## 7. 开发顺序

| 阶段 | 可演示结果 |
|---|---|
| 第一阶段：普通全栈 | 能创建、修改、保存、重新打开行程 |
| 第二阶段：AI 生成 | 输入需求后生成结构完整的行程 |
| 第三阶段：知识库 | 根据上传攻略回答，并显示真实来源 |
| 第四阶段：Agent | 自动选择工具完成任务，保存前请求确认 |

## 8. 验收标准

- 能完成“上传攻略 → 提问 → 生成行程 → 编辑 → 保存 → 重新打开”的流程。
- 输入三天，结果包含三天，每天有上午、下午、晚上的安排。
- 引用来自实际导入的资料；无相关资料时说明不足。
- 刷新页面后，已保存行程仍然存在。
- 模型或工具失败时有提示，可以重试。
- Agent 不无限调用工具，不未经确认保存行程。
- 模型密钥保留在后端。
