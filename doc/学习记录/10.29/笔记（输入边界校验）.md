## 学习笔记（待学习补充）

### 1. 从现有模型开始

2026-10-28 核对的 `backend/models.py`：

```python
days: int = Field(gt=0)
budget: float = Field(ge=0, allow_inf_nan=False)
```

当前天数必须大于 0，但没有业务上限；预算允许 0，不接受负数及非有限值。两个字段都没有默认值，当前为必填字段。

已经完成的首尾空白清理、拒绝纯空白文本、每日安排数量与天数一致、编号从 1 到最后一天依次排列不再重新讲解。本次在这些约束上补齐输入边界。

当前 POST /trips 只校验并返回输入，没有保存数据。不要把一次正常响应记为创建并保存了行程。

### 4. 边界验证清单

N 表示确认后的最大旅行天数。测试合法天数时，每日安排数量与编号也必须匹配，否则会被已有跨字段校验拒绝，无法据此判断上限规则是否正确。

| 场景 | 输入准备 | 预期结果 | 实际结果 |
| --- | --- | --- | --- |
| 最小合法天数 | days=1，安排一条且 day=1，预算为合法正数 | 200，返回校验后的输入 | 待验证 |
| 天数为 0 | 只将基准请求的 days 改为 0 | 422，包含天数约束错误 | 待验证 |
| 最大合法天数 | days=N，提供 N 条安排，编号 1～N | 200 | 待验证 |
| 超过最大值 | days=N+1，其余字段有效 | 422，包含天数上限错误 | 待验证 |
| 零预算 | 合法一日行程，budget=0 | 依据已确认规则填写 | 待验证 |
| 负预算 | 合法一日行程，budget=-1 | 422，包含预算约束错误 | 待验证 |
| 缺少预算 | 从合法请求中删除 budget 字段 | 422，提示字段缺失 | 待验证 |
| 缺少天数 | 从合法请求中删除 days 字段 | 422，提示字段缺失 | 待验证 |

非有限值规则保持现有约束；标准 JSON 不支持 NaN、Infinity 字面值，不将手工发送这些非法 JSON 的解析错误当作模型校验结果。
